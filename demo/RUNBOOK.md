# Demonstration Runbook & Troubleshooting Guide

This runbook provides step-by-step instructions to build, launch, test, and troubleshoot the EmbedJNoSQL demonstration suite.

---

## Prerequisites
- **JDK**: Java 17 or newer
- **Maven**: Not required; use the checked-in Maven Wrapper (`mvnw` / `mvnw.cmd`, Maven 3.9.6).
- **Network Access**: Access to Maven Central for initial framework dependency resolution.

---

## 1. Quick Start (Build & Test Everything)

Run the following commands from the repository root when you need to build from source. The
`v1.0.2` release and all seven artifact families are published and verified on Maven Central.

```bash
# 1. Verify core and install it for the independent Maven projects
./mvnw -B clean verify -Pcoverage-check
./mvnw -B install -DskipTests

# 2. Install framework modules and shared demo domain
./mvnw -B -f spring-boot-starter/pom.xml install -DskipTests
./mvnw -B -f quarkus-extension/pom.xml install -DskipTests
./mvnw -B -f micronaut-integration/pom.xml install -DskipTests
./mvnw -B -f demo/demo-common/pom.xml install -DskipTests

# 3. Test all nine framework/application demos
for m in spring-boot-demo quarkus-demo micronaut-demo vertx-demo \
         end-to-end-validation advanced-queries-demo annotation-showcase-demo \
         batch-processing-demo load-and-stress-demo; do
  ./mvnw -B -f "demo/$m/pom.xml" clean test || exit 1
done

# 4. Test all 20 single-feature core demos
for pom in demo/demos/*/pom.xml; do
  ./mvnw -B -f "$pom" clean test || exit 1
done
```

On native Windows PowerShell, use `.\mvnw.cmd` and repository-root paths. For example:

```powershell
.\mvnw.cmd -B -f demo\spring-boot-demo\pom.xml clean test
$poms = Get-ChildItem demo\demos -Directory | ForEach-Object { Join-Path $_.FullName 'pom.xml' }
foreach ($pom in $poms) {
    if (Test-Path $pom) {
        .\mvnw.cmd -B -f $pom clean test
        if ($LASTEXITCODE -ne 0) { throw "Demo failed: $pom" }
    }
}
```

Each project under `demo/demos/` is a self-contained Maven project that depends only on core;
it does not use `demo-common` or a framework integration.

The demos are generated by `demo/gen-demos.sh` from the `mainNN.txt` / `testNN.txt` templates.
After regeneration, review the diff because the generator rewrites all generated demo sources
and tests.

## 2. Running Standalone Demo Servers

### Spring Boot Demo
```bash
# Run from the repository root after following the install order above.
./mvnw -B -f demo/spring-boot-demo/pom.xml spring-boot:run
# Server runs on http://localhost:8080
curl http://localhost:8080/api/products
```

### Quarkus Demo
```bash
# Run from the repository root after installing quarkus-extension.
./mvnw -B -f demo/quarkus-demo/pom.xml quarkus:dev
# Server runs on http://localhost:8082
curl http://localhost:8082/api/products
```

### Micronaut Demo
```bash
# Run from the repository root after installing micronaut-integration.
./mvnw -B -f demo/micronaut-demo/pom.xml mn:run
# Server runs on http://localhost:8083
curl http://localhost:8083/api/products
```

### Vert.x Demo
Run the test suite or execute `EcommerceVerticle` programmatically:
```bash
./mvnw -B -f demo/vertx-demo/pom.xml test
```

## 3. Troubleshooting & Diagnostics

### Issue: "The process cannot access the file because it is being used by another process" (Windows)
- **Cause**: An unclosed `FileOutputStream` or `FileChannel` in persistent engines (`FileEngine`, `LSMTreeEngine`, `BTreeEngine`).
- **Remedy**: Always ensure `wal.close()` or `db.close()` is explicitly invoked in teardown blocks (`@AfterEach`). EmbedJNoSQL ensures all file descriptors, background flusher executors, and WAL sync threads are cleanly terminated upon `close()`.

### Issue: "No serializable introspection present for type Product" in Micronaut
- **Cause**: Micronaut serde requires `@Serdeable` or `@SerdeImport`.
- **Remedy**: In `SerdeConfiguration.java`, use `@SerdeImport(Product.class)` and `@SerdeImport(Order.class)` for external/shared records.
