"Why wait 8 seconds for Docker to spin up? I start in milliseconds, directly inside your JVM."

The NoSQL database that lives inside your JVM.

EmbedJNoSQL is a document and key-value database — plus Redis-style structures, wide-column families, and experimental vector search — in a single pure-Java JAR. No Docker. No daemon. No infrastructure.

Get started View on GitHub
Application.java 
// 1. Zero config — starts in milliseconds inside your JVM
EmbedJNoSQL db = EmbedJNoSQL.inMemory();

// 2. Schemaless documents with nested values
db.documentCollection("users").insert(
    Document.of("name", "Judicael")
        .add("address", Map.of("city", "Nairobi"))
        .add("role", "ADMIN"));

// 3. Dotted-path queries reach the nested fields
List<Document> inNairobi = db.documentCollection("users")
    .find(Query.eq("address.city", "Nairobi")
        .and(Query.eq("role", "ADMIN")));

// 4. Redis-style structures on the same engine
db.listBucket("events").rpush("events", "user_login");

One engine, four data models

EmbedJNoSQL has exactly one execution engine. Documents, key-value buckets, Redis-style structures, and wide-column families are data models on top of the same storage substrate — no second engine to configure, no dialect to keep in sync.

Model What it gives you Best for
Document Schemaless documents with native predicates ($eq $gt $regex $exists $and …), sorting, pagination, TTL, runtime secondary indexes, and dotted-path queries into nested values. Flexible schemas, entity mapping, application state, tests
Key-Value String buckets with per-key TTL, reachable from the same handle as every other model. Caches, session state
Redis-style Lists, sets, and hashes — queues, counters, and coordination primitives in-process. Queues, counters, coordination
Wide-Column Column families on the shared substrate, queried and written like every other model. Sparse records, high-cardinality rows
Shared by every model: pick in-memory, file (WAL), B-Tree, or LSM-Tree storage with a single flag — .withStorageEngine(StorageEngine.LSM). MVCC transactions, WAL recovery, the metrics/event bus, CDC, and the embedded Console work identically across all four. Experimental (not production features): HNSW vector search and the Kafka CDC connector — the file CDC connector is fully supported.
Framework starters & standards: 🍃 Spring Boot ⚡ Quarkus 🚀 Micronaut 🪐 Eclipse JNoSQL

Each starter auto-configures the engine — @Autowired EmbedJNoSQL db; — with health indicators, property bindings, and Repository support. Existing entities annotated with Jakarta Persistence, Eclipse JNoSQL, or Hibernate annotations are read as mapping hints at runtime: no JPA runtime, no JDBC driver, no rewrite.

The empty quadrant

For two decades, Java developers had two choices: embed H2 or SQLite (relational only), or spin up heavy external containers (MongoDB, Redis, Cassandra).

EmbedJNoSQL fills the missing quadrant: pure embedded, zero-infrastructure convenience with modern multi-model NoSQL flexibility.

Where EmbedJNoSQL stops

This is a NoSQL database: no SQL engine, no JDBC driver, no relational schema to migrate. Documents are schemaless unless you register validation rules, and a stored reference is an id you resolve yourself — never an enforced foreign key. We say so plainly, in the README and in every release note.
