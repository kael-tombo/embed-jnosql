- **Fixed in this audit**: R-01..R-09 (4 critical, 3 high, 2 others) — each with pre-fix failing evidence and post-fix green regression.
- **Fixed in improvement round 1 (2026-09-21)**: R-10, R-12, R-14, R-15, R-17, R-21, R-23, R-26 (CI gates, wrapper, CDC wiring, CORS, quarantine/atomic snapshots, WAL bound) — evidence in 64.
- **Fixed in improvement round 2 (2026-09-21)**: R-11, R-16, R-18, R-19, R-25, R-24, and the implementable half of R-20 (typed exceptions, index point lookup, vector dims, CLI recovery, audit persistence, atomic commits) — evidence in 63.
- **Fixed in this session (2026-09-21, CI validation round)**: R-27 — CI `demos` job root cause found and fixed (missing starter install for framework demos), diagnosed via new public per-demo annotations after local repro and falsification. Run #31 evidence: build(21)+size-gate ✅, build(23) ✅, integrations ✅, benchmark ✅; demos ❌ pre-existing since run #30 (not a regression of the byte-buddy exclusion).
- **Fixed in round 3 (2026-09-22)**: R-29 — standalone launch options now fail fast instead of silently ignoring unknown flags; R-30 — the same sweep applied to `BenchmarkRunner` and the CLI shell (including the silent zero-benchmark workload typo). Later the same day, live preview seeding exposed the **console-API data-integrity cluster**: R-31 (document update destroyed omitted fields + wrote a synthetic `name=temp`), R-32 (numeric schema rejected integral JSON numbers), R-33 (document TTL was dropped on every read, so nothing ever expired — doc 19's PASS was falsified and is corrected). All three fixed with regression tests; evidence in 66.
- **Found and fixed in the console live-validation round (2026-09-22, later)**: R-34 — the CDC "Subscribers" KPI was a copy of the event-log size; R-35 — **backups were empty by construction** (wrong enumeration + a fresh engine over a temp dir) yet reported success; R-36 — the restore route the console and the API's own documentation advertise had **never worked** (always 400), and its round-trip test had been passing vacuously; R-37 — an empty/malformed body to the backup endpoint dropped the TCP connection instead of returning an error; R-38 — the panel's Engine KPI always showed `—`. Each has a regression test that fails on the old code, plus live before/after evidence. All were found by **driving the running console**, not by reading code, and R-35/R-36 falsify doc 36's claim that backup was "exercised live with real payloads and error paths".
- **Found and fixed in the endpoint-integrity sweep (2026-09-22, same round)**: R-39 — CDC connectors were registered, started and displayed but **never subscribed**, so they delivered nothing; R-40 — the connector DELETE reported a successful disconnect for any name, and the POST dropped the connection on a missing field; R-41 — **`DELETE /api/indexes/{collection}` emptied the collection** (`clear()`) while reporting "indexes cleared", reproduced live as a 4 → 0 document loss. All fixed with regression tests and live before/after evidence. R-41 is the most serious defect found in this session after R-33: silent, unrecoverable data loss behind a route whose name promises index maintenance.
- **Found and fixed in the final endpoint sweep (2026-09-22)**: R-42 — transaction commit/rollback of an unknown id returned a fake `200 committed` (and the "rollbackted" typo); R-44 — bulk inserts silently discarded client-supplied ids, breaking GET-by-id for everything bulk-inserted. R-43 records a suspected metrics defect that probing showed to be **not a defect**, kept in the register so the semantics ("transactions begun") are written down. Both fixes verified live and covered by `ConsoleTransactionAndBulkTest` (8 tests) plus new blocks in the contract gate.
- **Found and fixed in the NoSQL query-operator sweep (2026-09-22, latest)**: R-45 — `$regex` used `String.matches()`, which implicitly anchors both ends, so the substring pattern `{"name":{"$regex":"Key"}}` (the natural reading of the parser's own documented style) **never matched anything**; any `$and`-joined query containing a `$regex` clause silently returned zero rows. R-46 — top-level `{"$and":[...]}` / `{"$or":[...]}` were **unreachable dead code**: their values are arrays, so `parseField` classified them as simple equality on fields literally named `$and`/`$or` and every document failed; confirmed live as `0 results` with a matching document present. R-47 — unknown operators were silently ignored (`default -> doc -> true`), so a typo like `{"$gteX":1}` returned **every document** as if no filter had been sent; now `QueryFormatException` → HTTP 400 naming the operator. Zero unit tests had ever covered `$regex`, `$and`, or `$or`. Fixes verified live on the preview (before: 0/0/4-rows-silent; after: 1/1/400) and by `ConsoleQueryEndpointTest` (11 tests, 9 of which fail at the pre-fix commit — falsified in a throwaway worktree at `08c4e4f`). `CoverageExtensionTest.queryParser_unknownOperatorIgnored` had codified the defect and was inverted to `queryParser_unknownOperatorRefused`. Contract gate extended with regex/`$and`/`$or` match-count assertions and 400 assertions.
- **Open**: R-13 (Maven Central staging — needs credentials), the mixed-writer half of R-20 (fundamental, documented in 13-T-03). R-28 (SQL Studio audit gap) was found in live preview validation and fixed the same day with regression tests. None are release blockers.
