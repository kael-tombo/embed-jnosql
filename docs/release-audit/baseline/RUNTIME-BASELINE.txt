# Runtime Baseline — Embedded Console

Captured 2026-09-23 on a real process (not a test harness).

Command:
  java -jar target/embed-jnosql-core-1.0.0.jar --port 18080 --engine IN_MEMORY

Startup (from server log):
  Storage engine: IN_MEMORY
  Flush mode: sync
  Server started successfully!
  API available at http://localhost:18080/api
  Health check at http://localhost:18080/api/health

## Probe results

| Probe | Result | Verdict |
|---|---|---|
| `GET /api/health` | `{"memory":{...},"status":"ok","engine":"IN_MEMORY","version":"1.0.0","open":true,"threads":{...}}` | PASS — real state, real telemetry |
| `GET /api/metrics` | real counters (`totalOperations`, `inserts`, `heapUsed`, `threadCount`, …) | PASS — not placeholders |

| `GET /api/collections/smoke` | returns the inserted document | PASS — read round-trip (writes/reads agree) |
| Cross-origin probe with `Origin: http://evil.example` | **no `Access-Control-Allow-Origin` header** | PASS — wildcard CORS is off by default (R-61 stays fixed) |

## Observed caveats (recorded honestly, not hidden)

1. **`Flush mode: sync` banner.** The startup banner prints `sync`, but R-67 records that
   `--sync`/`--async` are inverted in effect and that the banner overstates them. Durability does
   not depend on the flag (every write is fsynced to the WAL before acknowledgement), but the
   banner wording remains a documented defect. **Not re-fixed this round** — it needs the
   semantics decision recorded in R-67.
2. **SLF4J NOP logger.** Running the bare shaded jar logs
   `No SLF4J providers were found … Defaulting to no-operation`. This is expected: `slf4j-simple`
   is deliberately optional and excluded from the shaded jar so it cannot conflict with
   consumer logging backends. Standalone users who want logs must add a provider.

## Scope of this evidence

This proves the embedded server starts, serves the Console, answers health/metrics with real
data, round-trips a document, and does not expose wildcard CORS. It does **not** re-run the
console contract/auth gates across FILE/LSM_TREE/B_TREE (those were verified in the prior round;
see `TEST-BASELINE.txt`), and it does not re-run the crash-durability gate.
